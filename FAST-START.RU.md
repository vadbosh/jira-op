# Быстрый старт

Один экран. Полное руководство: [docs/setup.ru.md](docs/setup.ru.md) ·
[in English](FAST-START.md)

## Один раз

```bash
umask 077; read -r -s -p 'token: ' T \
  && printf 'JIRA_API_TOKEN=%s\n' "$T" > ~/.config/.jira/token.env && unset T
set -a; . ~/.config/.jira/token.env; set +a
jira init                     # Cloud, адрес сайта, login email, ключ проекта, доска
./install.sh                  # скил во все найденные ассистенты
jira me                       # печатает ваш login — значит работает
```

Токен идёт первым: `jira init` аутентифицируется по ходу своих вопросов и без
него падает с `401` на середине.

**Probe запускать не нужно.** `install.sh` сам считывает настоящие id полей
вашего проекта, когда файла сайта ещё нет; `add-site.sh` делает то же для
нового сайта. `jira-op-site-probe --write` нужен позже — когда конфигурацию
в Jira поменяли:

```bash
jira-op-site-probe --all --check   # что-то изменилось? ничего не пишет
jira-op-site-probe --all --write   # обновить все сайты
```

## Дальше просто говорите ассистенту

| Вы говорите | Что происходит |
|---|---|
| `покажи мои открытые задачи` | список, и всё |
| `что в активном спринте` | тот спринт, в который попадает сегодня |
| `разбери PROJ-123` | только чтение: факты, гипотезы, что проверить не удалось |
| `заведи таску: <что сделал>` | сначала черновик — без вашего «да» ничего не создаётся |
| `сделай недельный отчёт` | пишет `.txt` в рабочий каталог проекта, в ответ — путь |

## Заведение задачи

Спросят ровно две вещи: **story points** и **какой спринт**. Остальное берётся
из проекта или пишется в черновик. Эпик не проставляется никогда — привяжете
руками, если он нужен.

Черновик будет на английском, каким бы языком вы ни спрашивали. Посмотрите,
скажите «создавай». После записи задача вычитывается, и вам покажут, что
реально сохранилось.

**Созданную задачу откатить нельзя** на большинстве аккаунтов — никаких
пробных тикетов.

## Недельный отчёт

Календарная неделя, понедельник–воскресенье; запускать вечером пятницы или
утром субботы. Спросят, не попал ли в окно отпуск или праздники.

**Отчёт пишется в файл, в ответ приходит только путь.** Обычный текст с теми же
эмодзи-заголовками, в рабочем каталоге проекта — том, из которого запущен
ассистент:

```
weekly-update-2026-08-31_2026-09-06.txt
```

Как он выглядит: [docs/example-weekly-update.txt](docs/example-weekly-update.txt)

Содержимое в переписку не выводится, существующий файл не перезаписывается —
второй запуск создаст `-2`.

Чего он не делает: не публикует никуда, не пишет, сколько задача открыта, не
считает переносы между спринтами, не жалуется на пустые поля. Только факты
работы. Задачи в `To Do` не появляются вообще.

## Несколько сайтов Jira

```bash
jira-op-add-site acme      # спросит токен, запустит init, создаст SITE.acme.md
jira_site acme             # переключиться  (нужно: . ~/.local/share/jira-op/jira_site.sh)
jira_site default          # вернуться
```

## Если что-то сломалось

```bash
jira me                            # 401 — не тот токен или не тот email
jira-op-site-probe --all --check   # в проекте поменяли поля или статусы
```

Создание падает на незнакомом `customfield_*` — схему поменяли: запустите
`--write` и повторите.
