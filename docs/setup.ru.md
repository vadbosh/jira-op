# Установка: jira-cli, доступ и сам скил

Всё, что нужно, чтобы с пустой машины дойти до работающего `jira me`. Скил
работает через jira-cli; пока jira-cli не настроен, остальное не имеет смысла.

## 1. Поставить jira-cli

Готовые сборки для Linux, macOS и Windows лежат на
[странице релизов](https://github.com/ankitpokhrel/jira-cli/releases). Homebrew,
Nix и пакеты дистрибутивов перечислены в
[руководстве по установке](https://github.com/ankitpokhrel/jira-cli/wiki/Installation)
самого проекта.

Попробовать, ничего не устанавливая:

```bash
docker run -it --rm ghcr.io/ankitpokhrel/jira-cli:latest
```

Проверьте, что получилось. Эта документация написана под 1.7.0, и все флаги
ниже проверены на ней:

```bash
jira version
```

В более старых версиях флаги называются иначе. Если команда отсюда отклонена,
сначала прочитайте `jira <команда> --help`, а не считайте документацию неверной.

## 2. Получить API-токен

Для **Jira Cloud** токен создаётся на
<https://id.atlassian.com/manage-profile/security/api-tokens>.

От двух вещей зависит, заработает ли он:

- **Берите classic token — тот, что создаётся без scope.** Токены со scope
  принимают не все эндпоинты, которыми пользуется jira-cli.
- **Login email должен принадлежать аккаунту, создавшему токен.** Несовпадение
  даёт `401 Unauthorized`, который выглядит как плохой токен, хотя дело не в нём.

Для **on-premises** Jira подходит либо пароль от учётной записи (тип
аутентификации `basic`), либо personal access token (тип `bearer`, при этом
нужно экспортировать `JIRA_AUTH_TYPE=bearer`). Поддерживается и mTLS с
клиентскими сертификатами — тип `mtls` при инициализации.

## 3. Сохранить токен

jira-cli читает токен **только** из переменной `JIRA_API_TOKEN`. В файл
конфигурации он не записывается.

```bash
umask 077
read -r -s -p 'token: ' T \
  && printf 'JIRA_API_TOKEN=%s\n' "$T" > ~/.config/.jira/token.env \
  && unset T
```

`read -s` не выводит значение на экран и не оставляет его в истории команд.
Загрузка в любой оболочке:

```bash
set -a; . ~/.config/.jira/token.env; set +a
```

Авторы jira-cli предлагают экспортировать переменную прямо из `~/.bashrc` и
поддерживают `.netrc` и связки ключей. Здесь выбран отдельный файл с правами
`600` по одной причине: его можно подменять для разных сайтов, а экспорт в
`.bashrc` — нет.

**Ассистент-кодер снимает окружение при запуске.** Переменная, экспортированная
в терминале уже после старта ассистента, до него не доходит — поэтому скил
загружает файл внутри каждой команды, а не полагается на унаследованное
значение.

## 4. Запустить jira init

Сначала экспортируйте токен. `jira init` во время своих вопросов ходит на сайт,
поэтому без токена в окружении он падает с `401` на середине и не оставляет
ничего.

```bash
set -a; . ~/.config/.jira/token.env; set +a
jira init
```

Ответы:

| Вопрос | Что отвечать |
|---|---|
| Installation type | `Cloud` для `*.atlassian.net`, `Local` для on-premises |
| Link to Jira server | полный адрес сайта, например `https://example.atlassian.net` |
| Login email | аккаунт, которым создан токен |
| Default project | **ключ** проекта, а не отображаемое имя: `OPS`, а не `Operations` |
| Default board | доска, на которой вы действительно работаете |

Два ответа, на которых спотыкаются чаще всего:

- **Ключ проекта, а не название.** Если работа видна в левой панели Jira в
  разделе *Spaces* — это Confluence, а space Confluence не является проектом
  Jira. Ключ — это префикс ваших задач: `ABC-1234` → `ABC`.
- **Доска важна.** Без доски или с неверной доской любая спринтовая команда
  ответит `No result found`.

Всё то же самое передаётся флагами, без вопросов:

```bash
jira init --force --installation cloud \
  --server https://example.atlassian.net \
  --login you@example.com \
  --auth-type basic \
  --project ABC --board "ABC Sprint board"
```

Конфигурация ложится в `~/.config/.jira/.config.yml`. Учётных данных в ней нет.

## 5. Проверить

```bash
jira me                                  # печатает login — аутентификация работает
jira project list | head                 # доступ к проектам
jira issue list -a"$(jira me)" --plain --paginate 15
jira sprint list --state active --plain  # нужна доска в конфигурации
```

`jira me` подтверждает учётные данные и ничего больше. Права на конкретный
проект или задачу — отдельный вопрос, и `jira project list` отвечает на него
дешевле всего.

Что аккаунт может делать в проекте:

```bash
SITE=https://example.atlassian.net
curl -s -u "$(jira me):$JIRA_API_TOKEN" \
  "$SITE/rest/api/3/mypermissions?projectKey=ABC&permissions=CREATE_ISSUES,EDIT_ISSUES,DELETE_ISSUES,TRANSITION_ISSUES" \
  | jq -r '.permissions | to_entries[] | "\(.key)\t\(.value.havePermission)"'
```

Запустить стоит один раз. `DELETE_ISSUES: false` встречается часто и означает,
что ошибочно созданная задача останется на доске, пока её не удалит
администратор.

## 6. Поставить скил

```bash
./install.sh              # во все каталоги ассистентов, найденные в $HOME
./install.sh --dry-run    # показать действия, ничего не менять
./install.sh --skills-dir ~/куда-нибудь/skills
```

Скрипт ищет `~/.claude/skills`, `~/.config/opencode/skills` и
`~/.codex/skills` и пишет только туда, где родительский каталог уже существует.
Если содержимое в месте назначения отличается от исходного, оно копируется в
`<каталог>.bak.<метка времени>` до замены.

**Только Linux и macOS** — это скрипт на bash. Под Windows берите WSL или Git
Bash либо скопируйте каталог вручную:

```
skills\jira-op  ->  %USERPROFILE%\.claude\skills\jira-op
                ->  %USERPROFILE%\.codex\skills\jira-op
                ->  %APPDATA%\opencode\skills\jira-op
```

Сам скил — это Markdown, на shell написан только установщик. `tools/add-site.sh`
и `tools/jira_site.sh` тоже на bash, поэтому в родном Windows переключение
между сайтами делается заданием `JIRA_CONFIG_FILE` и `JIRA_API_TOKEN` вручную.

Перезапустите ассистента или начните новую сессию, чтобы он перечитал скилы.

## 7. Несколько сайтов Jira

Один файл конфигурации описывает один сайт, а токен один на процесс.
Переключаться они обязаны вместе: конфигурация одного сайта с токеном другого
даёт `401`, который читается как протухший токен, а не как неверная пара.

Завести сайт:

```bash
./tools/add-site.sh acme
```

Скрипт сначала спрашивает токен и экспортирует его, затем запускает `jira init`
для `~/.config/.jira/acme.yml` и только после успешного init записывает
`~/.config/.jira/acme.token.env` с правами `600`. Дальше он перепроверяет
сохранённую пару в чистом окружении, то есть проверяет именно то, что лежит на
диске. Если init упал, конфигурация удаляется, токен на диск не попадает.

```bash
./tools/add-site.sh --list      # что уже заведено
```

Переключение — функцией оболочки:

```bash
. /путь/к/jira-op/tools/jira_site.sh    # или подключить из ~/.bash_aliases

jira_site acme      # ~/.config/.jira/acme.yml + acme.token.env
jira_site wl        # обратно на .config.yml + token.env
```

Она печатает login — это и есть доказательство переключения. Действие
ограничено текущей оболочкой.

**Всё, что в скиле привязано к проекту, на другом сайте недействительно** — тип
задачи, идентификаторы кастомных полей, статусы, номер доски. Перед любой
записью перечитайте `createmeta`; см. раздел «Настройка под свою Jira» в README.

## Как поддерживать файлы сайтов в актуальном состоянии

`SITE.md` — это снимок конфигурации проекта Jira, а Jira меняется, никого не
предупреждая. Актуальность держат три команды:

```bash
tools/site-probe.sh --write          # перегенерировать для текущего сайта
tools/site-probe.sh --all --write    # для всех заведённых сайтов
tools/site-probe.sh --all --check    # показать расхождение, ничего не писать
```

`--check` возвращает `3`, когда живой API расходится с тем, что на диске, —
поэтому годится для cron. **Автоматически его никто не ставит**: клон
репозитория не должен трогать ваш crontab. Добавьте сами, поправив пути:

```cron
# раз в неделю, только чтение; при изменении проекта — код 3 и diff в логе
23 9 * * 1 PATH=/usr/local/bin:/usr/bin:/bin HOME=/home/you \
  /path/to/jira-op/tools/site-probe.sh --all --check \
  >> /home/you/.local/state/jira-op/site-check.log 2>&1
```

cron запускается с урезанным окружением: задайте `PATH`, чтобы нашлись `jira`
и `jq`, и `HOME`, чтобы разрешились конфиг и файл с токеном.

`add-site.sh` и `install.sh` создают файл сами, когда его нет, поэтому в
обычном случае команда не нужна вовсе.

### Когда скил правится не на месте

На машине, где скил лежит в одном каталоге и копируется в ассистентов — канон
конфигурации, git-клон, общая папка, — запись в копию ассистента отменяется
следующей синхронизацией. Укажите инструменту исходный каталог:

```bash
export JIRA_OP_SKILL_DIR=~/config-canon/skills/jira-op
```

Флаг `--skill-dir` по-прежнему главнее переменной.

## Разбор ошибок

| Симптом | Причина и что делать |
|---|---|
| `401 Unauthorized` при `jira init` | токена нет в окружении либо login email не тот аккаунт, что создал токен. Экспортировать токен, проверить почту |
| `401` после переключения сайта | конфигурация и токен от разных сайтов. Загружать пару целиком |
| `403` на проекте | у аккаунта нет доступа. Обращаться к администратору Jira |
| `✗ Missing configuration file.` | `JIRA_CONFIG_FILE` указывает на несуществующий файл. Снять переменную или выполнить `jira init` для этого пути |
| `No result found for given query in project "X"` | проект по умолчанию в конфигурации не тот. Передать `-p KEY` или переинициализировать `jira init --force` |
| `No boards found in project "X"` | та же причина. В сообщении назван проект из конфигурации, а не тот, о котором спросили |
| Спринтовые команды ничего не возвращают | в конфигурации нет доски либо стоит kanban там, где нужна scrum |
| `400 Bad Request: Expecting ',' but got 'ORDER'` | `ORDER BY` внутри `-q`. Использовать `--order-by` |
| `Error: unknown flag: --plain` | у `board list` нет флагов вывода. Читать таблицу или брать Agile REST API |
| Список подозрительно короткий | `--paginate` по умолчанию равен 8. Передавать `--paginate 15` |
| У обсуждавшейся задачи не видно обсуждения | `issue view` показывает один комментарий. Передавать `--comments 10` |
| В терминале работает, в ассистенте нет | ассистент снял окружение при запуске. Загружать файл с токеном внутри команды |

## Удаление

```bash
rm -rf ~/.claude/skills/jira-op ~/.config/opencode/skills/jira-op ~/.codex/skills/jira-op
```

Конфигурация jira-cli и файлы с токенами лежат отдельно и этой командой не
затрагиваются. Удалять их нужно осознанно:

```bash
rm -i ~/.config/.jira/.config.yml ~/.config/.jira/token.env
```

Сам API-токен отзывается на
<https://id.atlassian.com/manage-profile/security/api-tokens> — удаление
локального файла его не аннулирует.
